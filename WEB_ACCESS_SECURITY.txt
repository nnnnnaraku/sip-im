This branch contains no audio P0, group-chat, file-security or video-diagnostics implementation.

1. What changed
The previous HttpServer bound every interface; API/SSE/received files had no authentication.
Dial, hangup, recording and send handlers accepted methods without a unified boundary.
No shared CSRF, Host, cross-origin or body limit protected the controls.
The contacts UI inserted untrusted SIP user names with innerHTML.

The single root dispatcher is now wrapped in WebAccessControl:
- Loopback 127.0.0.1 by default; actual remote peer must be loopback in local mode.
- Public GET / and /web-access.js contain no credentials or client state.
- Every /api/* and /files/* route requires a private capability login and session.
- Login: POST /api/session/login; application/json; X-SIP-Login: 1; JSON token in BODY.
- GET /api/session restores the session and returns its CSRF token to same-origin JavaScript.
- POST /api/session/logout requires the session cookie and X-SIP-CSRF.
- Mutating controls require POST + authenticated cookie + matching X-SIP-CSRF.
- Origin (when present), Host and Sec-Fetch-Site are checked independently of authentication.
  Omitting or forging Origin never substitutes for credentials/CSRF.
- No CORS authorization, wildcard Host, proxy/forwarded-header trust or URL credentials.
- Unknown API prefixes/suffixes are denied; old HttpServer prefix-handler fallthrough removed.
- URI <=2048 chars; application header budget 16KiB.
- Text <=16KiB UTF-8; file upload <=16MiB; login <=1024 bytes;
  future group JSON <=4096 bytes; remaining controls/read endpoints accept no body.
- Ambiguous Content-Length/Transfer-Encoding, bad UTF-8 and malformed session JSON rejected.
- HttpOnly, SameSite=Strict cookies; HTTPS adds Secure. Cookie name includes Web port.
- 30-minute idle / 8-hour absolute session lifetime, 8 sessions per process.
  SSE checks validity on every event and heartbeat; heartbeat does not renew idle lifetime.
- Login attempts: 10 per peer / 5 min, 50 process-wide / 5 min; peer table bounded.
- SSE capped at 4 streams so the 8-worker pool still has capacity for controls.
- no-store, nosniff, no-referrer, DENY framing and restrictive same-origin CSP.
- Error responses no longer echo underlying SIP/file exception details.
- Contact labels use textContent. Conference UI uses Map rather than untrusted selectors.

2. Configuration and first login
Use an independent PRIVATE run directory and its existing SIP configuration; do not overwrite
a tested release/configuration. This change does not alter SIP/RTP/media/server ports.
In that private configuration:
  web.port=8081
  web.bind.address=127.0.0.1
  web.remote.enabled=false
  web.allowed.hosts=
  web.auth.token.file=web-access.token
  web.tls.keystore=
  web.tls.password.file=
  web.tls.keystore.type=PKCS12

First authorized WebClientServer startup creates the token at the configured path,
using CREATE_NEW and owner-only ACL (Windows) or 0600 (POSIX).
The parent directory must already exist and be trusted, with no junction/symlink aliases.
Existing invalid/wide-permission/token files are rejected, never silently overwritten.
The console prints the token FILE PATH, never its value. Open that private file locally,
paste its one line into the login form, then close the editor. Do not paste it into
chat, terminal commands, evidence screenshots, public configs or source files.
The page clears the password input; it stores neither access nor CSRF tokens in localStorage,
sessionStorage, URLs or logs. Keep one spelling of the origin (127.0.0.1 or localhost)
during a session. Cookies are host scoped: these two names have separate login state.

Local multi-instance example (private directories, not automatically created here):
  A: web.port=8081; web.auth.token.file=web-access-100.token
  B: web.port=8082; web.auth.token.file=web-access-101.token
  C: web.port=8083; web.auth.token.file=web-access-102.token
Existing SIP, RTP, video and log directory isolation is still required.
A token is a Web control capability, NOT a SIP password or an administrator password.

3. Explicit remote mode — only if later approved
Do not change A/B/C deployment or firewall for this task.
To opt in, provide all of the following in a private config:
  web.remote.enabled=true
  web.bind.address=<one concrete LAN IPv4>
  web.allowed.hosts=<optional exact DNS names, comma-separated, no scheme/port>
  web.tls.keystore=<absolute private PKCS12 or JKS path>
  web.tls.password.file=<absolute private UTF-8 single-line password file>
  web.tls.keystore.type=PKCS12
The bind address is automatically an allowed Host; wildcard binding is rejected.
Remote mode without TLS, partial TLS settings, invalid TLS or overly broad private-file
permissions fail before a listener is bound. TLS is explicitly limited to 1.2 for Java 8.
Provision a certificate whose SAN matches the address/name and trust it on the intended browser.
Certificate creation/trust installation is a separate operator action; none was done here.
The keystore (<=1MiB), password (<=4096B) and token (<=128B) must belong to the current OS
user and grant access only to that user. Protect these files in an owner-controlled directory.
Do not use curl -k, browser warning bypasses or plaintext remote credentials as acceptance.

8. Remaining limits
This is a single-owner PC-client control capability, not a multi-user/roles identity system.
Same-host malicious programs, OS administrators, compromised browser extensions or same-origin
XSS are outside this boundary. Cookies are NOT isolated from every service on the same hostname;
port-qualified names prevent accidental multi-instance collisions, not malicious local services.
Legacy inline JS/style requires CSP unsafe-inline; nonce migration is a later change.
Java8 path checks still depend on a trusted parent directory; they are not an OS-level sandbox.
Login/logout does not automatically hang up a live call. If authentication expires mid-recording,
the UI cannot issue a new privileged stop; an operator must reconnect/stop the existing process.
SSE resources are released on error/heartbeat (<=15 seconds for quiet disconnected streams).
A slow authenticated reader can still slow broadcast; this change is not a streaming-system rewrite.
Bounded payloads do not provide comprehensive slow-client/DoS protection or a public Internet gateway.
The legacy file storage/path issues remain for the separate file-security change.
AdminServer is a different process and is not protected by this Web-client guard.
MssClient's existing upstream miniSIPServer authorization uses a password query parameter;
that legacy upstream contract and its configuration were not changed here. New Web credentials
never use query parameters. Existing public example SIP/admin passwords remain template values,
not a recommendation for real deployments.
